# 데이터 보관·삭제

필요한 만큼만 받고, 필요 없어지면 지워요. 정리는 모두 새벽 배치가 해요 (KST, 하루 한 번, 몇 번 돌아도 결과가 같아요).

| 데이터 | 보관 | 지우는 곳 | 시각 |
| --- | --- | --- | --- |
| 작업 구간 `activity_segment` | 끝난 지 186일 | `ActivityRetentionJob` | 04:30 |
| 하루 요약 캐시 `daily_activity` | 187일 전 날짜까지 | `ActivityRetentionJob` | 04:30 |
| 둘이 함께한 날 `together_daily` | 6개월 | (TGTR-1에서 더함) | |
| 꾹 `squish` | 전달 후 30일, 안 받은 것도 30일 | (SQSH-3에서 더함) | |
| 접속 상태 (Redis) | 하트비트가 끊기면 90초 | Redis TTL | |
| 로그인 중 상태·1회용 코드 (Redis) | 10분·60초 | Redis TTL | |
| Refresh Token `refresh_token` | 만료·폐기 후 7일 | `RefreshTokenCleanupJob` | 04:50 |
| 탈퇴 계정 | 탈퇴 후 7일 (그 안에 다시 로그인하면 복구) | `WithdrawnUserPurgeJob` | 04:40 |

## 왜 이렇게

- **작업 구간 186일**: 친구 프로필 잔디가 17주(약 4개월)라 여유를 두고 6개월만 남겨요. 하루 기록도 6개월 전까지만 보여줘요.
- **폐기된 Refresh Token 7일**: 바로 지우면 훔친 토큰이 다시 와도 "없는 토큰"으로만 보여서, 그 기기를 끊는 재사용 감지가 동작하지 않아요.
- **탈퇴 7일 유예**: 실수로 탈퇴해도 되살릴 수 있게요. 지나면 사용자 행까지 모두 지우고, 같은 소셜 계정으로 다시 로그인하면 새 계정이에요.
- **나눠 지우기**: 큰 DELETE 하나는 잠금을 오래 잡아서, 1,000개(계정은 100명)씩 나눠 지워요.

## 받지 않는 것

입력 내용, 앱 이름, 창 제목, 이메일은 받지도 저장하지도 않아요. 소셜 계정은 제공자 안에서 고정된 id(Google `sub`, GitHub `id`)로만 찾아요.
