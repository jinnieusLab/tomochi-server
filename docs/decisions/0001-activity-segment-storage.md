# 0001. 작업 구간은 받은 그대로 저장하고, 읽을 때 합친다

- 상태: 채택 (2026-10-19) · **재검토 예정** — ACT-2(하루 기록), TGTR-1(둘이 함께한 시간) 할 때 다시 봐요
- 관련: #15 (ACT-1), 기능 정의서 3.3

## 상황

기능 정의서는 "내 다른 구간과 겹치면 합쳐서 하나로 저장"이라고 해요. 목적은 기기를 여러 대 켜 둬도 시간을 두 번 세지 않는 거예요.

```text
맥북    09:00 ─────── 10:00
아이맥         09:30 ──────────── 11:00
실제로 일한 시간  09:00 ─────────────────── 11:00   = 2시간 (그냥 더하면 2시간 30분)
```

그런데 앱은 열린 구간을 5분마다 **같은 `clientSegmentId`로 늘려서** 다시 보내요. 저장할 때 합쳐 버리면 맥북이 `09:00~10:30`을 같은 id로 다시 보낼 때, 합쳐진 `09:00~11:00` 행 안에서 맥북 몫이 어디였는지 알 수 없어요.

## 선택지

| | 저장할 때 합치기 (정의서) | **받은 그대로 저장, 읽을 때 합치기** |
| --- | --- | --- |
| 저장 | 겹치는 행을 찾아 하나로 합치고 하루 상한을 잘라 저장 | `clientSegmentId`별로 그대로. 같은 id는 범위만 넓힘 |
| 같은 id 재전송 | id → 합친 행 매핑 테이블이 더 필요 | `INSERT … ON DUPLICATE KEY UPDATE` 한 번 |
| 동시 업로드 | 사용자 행 `SELECT … FOR UPDATE`로 직렬화 | 잠금 없음 (`LEAST`·`GREATEST`는 순서와 상관없이 같은 결과) |
| 읽기 | 더하기만 하면 됨 | 합집합 계산 O(n log n) |
| 하루 20시간 상한 | 저장할 때 잘라 둠 | 읽을 때 적용 |

## 결정

**받은 그대로 저장하고, 읽을 때 합집합으로 계산해요.**

- `activity_segment (user_id, client_segment_id)` 유니크. 같은 id가 다시 오면 `started_at = LEAST(…)`, `ended_at = GREATEST(…)`로 넓히기만 해요. 늦게 도착한 옛 요청이 범위를 줄이지 않아요.
- 한 요청 안의 여러 구간은 id 순서로 저장해서, 두 요청이 같은 id들을 반대 순서로 잠가 데드락이 나지 않게 해요.
- 하루 시간·30분 칸은 `DailyActivity.calculate`가 그 사용자 구간의 합집합을 사용자 시간대의 하루로 잘라 계산해요. 20시간을 넘으면 시간 순으로 뒤에서부터 잘라요.
- 친구와 겹친 시간(TGTR-1)도 각자의 합집합을 먼저 구한 뒤 두 포인터로 겹침을 계산해요.

## 결과

- 좋은 점: 저장이 단순하고 잠금이 없어요. 원본이 남아 있어서 규칙(상한, 칸 크기)을 바꿔도 다시 계산할 수 있어요.
- 나쁜 점: 읽을 때마다 합집합을 계산해요. 지난 날은 `daily_activity` 요약 캐시(ACT-2)로 줄일 예정이에요.

## 하루 요약 캐시 (#16에서 더함)

읽을 때마다 합집합을 계산하는 비용을 줄이려고 지난 날은 `daily_activity`에 캐시해요. 캐시는 **지우지 않아도 되는 날만** 넣어요.

- 업로드는 시작이 7일보다 전인 구간을 거절해요. 그래서 **하루가 끝난 지 7일(+ 시계 차이 2분)이 지난 날**에는 새 구간이 걸칠 수 없어 값이 확정돼요. 이런 날만 저장해요.
- 최근 7일과 오늘은 매번 구간에서 계산해요. 늦게 올라온 구간이 바로 반영돼요.
- 캐시 행에 계산할 때의 시간대를 같이 저장해요. 사용자가 시간대를 바꾸면 날짜 경계가 달라지니, 시간대가 다른 행은 쓰지 않고 새로 계산해 덮어써요.

이렇게 하면 업로드·시간대 변경 때 캐시를 지우는 코드가 없고, "지우는 순간과 읽어서 다시 넣는 순간이 엇갈려 옛 값이 남는" 경쟁도 생기지 않아요.

## 다시 볼 것

- 읽기 비용이 캐시로 충분한지 (특히 17주 잔디, 친구 쌍 집계)
- 하루 상한을 읽을 때 적용하는 게 맞는지, 아니면 저장할 때 막아야 하는지
- 같은 사용자의 겹치는 원본 행이 많이 쌓이는 경우 (기기 여러 대를 오래 켜 둠)
